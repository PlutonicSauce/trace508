# Assurance demo

1. Start PostgreSQL, `npm run dev`, `npm run worker`, and (with ENABLE_LAB=true) `npm run lab`. Create/sign in with your real administrator account.
2. Show existing actual W3C scans and explain that a clean automatic scan is not Supports. No reviewer decisions are seeded into the live workspace.
3. Create/select an isolated fixture project, initialize Controlled test lab, and assess its first home page and second site's form. Show their distinct actual image/label findings.
4. Inspect a finding's selector, HTML, screenshot, raw JSON, source hash and criterion association. Generate draft ACR version 1 and an independent evidence package.
5. Save an actual lab build change by enabling alternative text or form labels. Open the resulting website to inspect the new HTML. Existing evidence remains unchanged.
6. Record a remediation proposal/implementation claim. Click Run independent retest. Show a new assessment and browser run, the changed build label, and its conclusive rule outcome.
7. Return to the original issue lifecycle. Explain automated-no-longer-detected, human-verification-required and criterion conformance as separate concepts. Record only actual human test observations under your authenticated account.
8. Generate the next draft report from the retest. Show version history, removed findings/new evidence, DOCX and schema-validated partial OpenACR. Unresolved criterion claims remain blank/omitted.
9. Reintroduce the controlled defect, run a new independent retest and show regression reopening with original and intervening evidence intact.
10. In Journey assurance, configure goto form, fill invalid email, click submit, fill valid email and click submit. Enable state scans at the form, error and recovery states. Show persisted transitions, source DOM/screenshots and manual criterion tasks.
11. Register another authorized public HTTPS target in Project & access and scan it with no source edits. Show roles, account revocation, project isolation, retention/deletion controls and the project audit log.
12. Keep the W3C Before/After comparison available as an independent benchmark. Do not claim 90% discovery, signed evidence, completed official VPAT, or successful ORAP/GAT/Gemini integration without the corresponding evidence.
